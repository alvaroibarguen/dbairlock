# Phase 11: accessibility and polish (workstream `a11y`)

Branch `p11-a11y`. Changes are in `web/` plus two token values in `DESIGN.md`, a regenerated `docs/images/review.png` and one row in `docs/VERSIONS.md`. No Go changes were needed.

## What was added

- `@axe-core/playwright` 4.14.0 (latest; axe-core 4.14) and `web/e2e/axe.ts`, a helper that runs axe with the WCAG 2.0/2.1/2.2 A and AA tags plus best-practice rules, once in the dark and once in the light theme (through `prefers-color-scheme`, with reduced motion so colour transitions do not skew the contrast check).
- `web/e2e/a11y.spec.ts`: axe on every page at 1280 px (desktop project) and 375 px (mobile project): sign-in (plain and with an error), recovery link without a code, the queue in all three views, a missing change, a change with rows as its author and as a reviewer, the affected-rows tab on a phone, the reject dialog, the new change editor empty and with a preview, the audit log, an audit event drawer, the audit log with no matches, connections (list, new, detail, schema), connect an agent, every settings section as admin, settings as a member, the create-token and demote-admin dialogs, the 404 page, the queue's error state (API answering 500), the user menu and the phone navigation drawer. `setup.spec.ts` runs axe on every setup wizard step, and on the first step at 375 px too.
- `web/e2e/keyboard.spec.ts` (both projects, no clicks): ada opens the editor from the navigation (the drawer on a phone), picks the connection with the keyboard, types title, reason and SQL, previews with Mod+Enter and submits; bob skips to content, Tabs to the change in his queue, opens it and approves with Mod+Enter, and the server executes it. Also: the reject dialog traps focus, Escape returns focus to Reject, and rejecting works by keyboard; an audit event drawer opens and closes by keyboard and focus returns to the row; settings sections and the user menu by keyboard.
- `web/e2e/layout.spec.ts` (mobile project): every page at 375 px, including a change with a long title and SQL, its rows tab, a connection's schema and the editor with a preview, must not scroll sideways and must not have any element sticking out of the viewport unless it sits inside its own scroll box. `A11Y_SHOTS=<dir>` also saves a screenshot of each page; I reviewed all of them by eye in the light theme.

Result: the full Playwright suite passes (104 passed, 23 skipped by design: the screenshot test and the desktop-only/mobile-only splits) with the sample targets running. `make lint`, `make build` and the web unit tests pass.

## What axe and the keyboard/375 px checks found, and the fixes

1. **Contrast (WCAG 1.4.3).** Three tokens failed 4.5:1 where they are actually used:
   - dark `--mute` `#8a919b` on `--raise` (menus, drawers, dialogs, selected rows): 4.29. Now `#9299a3` (4.74 on raise, 5.34 on panel).
   - light `--mute` `#6b7280` on `--bg` (4.43) and on `--raise` (4.23). Now `#646b77` (4.92 / 4.70).
   - light `--amber` `#b45309` on its own 8% tint (4.49, warnings and the pending badge). Now `#a94d08` (4.61 on the tint over bg).
   - light `--green` `#17803d` as string colour in the editor's active line (4.47) and on its tint (4.15 over bg). Now `#147838` (4.96 / 4.58; white on the primary button is 5.57).
   DESIGN.md's token table is updated to match. The differences are a few percent of lightness and do not change the look (see the regenerated `docs/images/review.png`). Also removed `opacity-80` from the sign-in/setup error code and `text-mute/80` from the change header, which pushed text below 4.5:1. `docs/design/review-screen-reference.html` still has the old hex values; it is the static reference of the chosen direction and was left as is.
2. **Accessible names that do not contain the visible text (WCAG 2.5.3).** The logo's "ab" was text inside the "dbairlock home" link, and the avatar initials were text inside the "User menu" button. Both are now drawn with CSS `content` (no inline styles, CSP safe) so speech-input users can say the visible label. The audit log's phone list items had an `aria-label` that hid their time, actor and subject; they are now named by their visible text. `audit.spec.ts` accepts both names (the desktop table keeps its label, which contains the visible text).
3. **Scrollable regions not reachable by keyboard (WCAG 2.1.1).** SQL blocks, data tables and the before/after row tables scroll sideways but could not be focused. New `useScrollFocus` makes such a box a Tab stop only while it actually overflows.
4. **Missing level-one heading** on phone screens where the detail replaces the list: the affected-rows tab, a missing change, and connection detail/new. Each now has an h1 (visible where it adds a way back, screen-reader-only otherwise). **Heading order**: the editor's preview on narrow screens had h3s with no h2 (added the section heading), and a connection's schema on a phone now has its h1 above the h2.
5. **Page scrolled sideways at 375 px** on Settings → Users: a screen-reader-only "Actions" header is absolutely positioned and escaped the table's scroll box, widening the page to 568 px. Tables and row diffs are now `position: relative`. No other page overflowed.
6. **Focus lost after navigation.** Opening a change from the queue re-rendered the queue, so focus fell to `<body>` and a keyboard user restarted at the top of the page. The shell now moves focus to the selected queue row when there is one, otherwise to `<main>`, whenever a navigation leaves focus nowhere.
7. **Focus not returned when a dialog closed.** Dialogs opened from state (Reject, Cancel, the audit event drawer, the new demote dialog) left focus on `<body>` after Escape. `Dialog` and `Drawer` now return focus to the element that opened them (Base UI `finalFocus`), when it still exists.
8. **Page titles (WCAG 2.4.2).** Every page had the tab title "dbairlock". Each page now names the tab ("Audit log · dbairlock", "API tokens · Settings · dbairlock", "Change #12 · dbairlock").

## Loading, empty and error states; confirmations

Every page already had loading and error states for its main data; these gaps were filled:

- Change activity timeline: the error was a bare red message; it now says what failed and has Retry. An empty timeline says "No activity yet."
- New change: the connection list's failure was silent (an empty dropdown); it is now the field's error. With no connections, the field says so and links to Connections.
- Edit change: the load error had no action; it now has Retry and the error code.
- Sign-in and setup pages: a failed `/api/meta` request now shows an error (setup: with Retry) instead of a blank instance name or the wrong step.
- The rows pane of a change that failed to load said "No affected rows to show"; it now says the change could not be loaded (the detail pane carries the Retry).

Destructive actions: reject, cancel, archive connection, revoke token and remove user already asked first; clearing a secret is staged until Save with Undo. **Demoting an admin to member took effect immediately from the role dropdown**, including demoting yourself; it now asks first and names the consequence ("Make yourself a member?" ... "Only another admin can undo this."). Granting admin still applies at once.

## Copy

All interface strings were read once. The copy was already plain and named reasons; changes were small: "Something went wrong." fallbacks became "The request did not complete. Try again." (and the real error message is shown when there is one), "Sign-out failed." became "You could not be signed out. Try again.", "This connection could not be loaded." matches the other "The X could not be loaded." titles.

## Not fixed / not verified

- axe's best-practice `region` rule flags Base UI menus, listboxes and tooltips because they are portalled to `<body>` outside any landmark. These are transient popups owned by their trigger, so `web/e2e/axe.ts` treats them as regions, as axe already does for dialogs. Their content is still checked by every other rule.
- Screen readers were not tested by hand (no NVDA/VoiceOver on this machine); the checks are axe, the accessibility tree as Playwright sees it, keyboard-only tests and screenshots.
- At 375 px the Users table and the settings section tabs scroll sideways inside their own boxes (the Remove button is off to the right until you scroll). This is reachable and passes the checks, but a stacked layout per user would be nicer on phones.
- Dark theme screenshots at 375 px were not reviewed by eye; dark is covered by axe (contrast included) on every page.
- Outside this workstream's scope, seen while running `make test` on this branch (no Go code changed here): `TestConformance/mysql9/database/unavailable/connection_killed_after_begin` in `internal/connector/mysql` failed once with "Execute = target unavailable: invalid connection; a connection lost after BEGIN must not be ErrUnavailable", and passed when rerun alone. Under heavy machine load the MySQL connector can classify a connection lost after BEGIN as "unavailable" (retryable) instead of an uncertain outcome. That is a fail-closed question for the safety/robustness workstreams to look at, not a test to retry.
- `src/test/boundaries.test.ts` (ESLint-based, 5 s default timeout) timed out once under a load average of 35 from the parallel workstreams, and passed on rerun; it is a timing flake, not a failure.
